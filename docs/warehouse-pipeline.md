# Общий обзор, товары ИНТЭР и штрихкоды

В одном процессе распознавания можно включать три независимых модуля:

```text
Исходный кадр
  ├─ WarehouseLogistics ONNX → общие объекты
  ├─ YOLO .pt → товары из вашего каталога
  └─ ZXing-C++ → точное содержимое Code128 / EAN / QR / Data Matrix
                        ↓
         рамки, подписи и список прочитанных кодов
                        ↓
         выбор товара и подтверждение оператором
```

Общий класс `barcode` означает найденную область. Только результат декодера считается
прочитанным кодом. Проценты детектора не являются вероятностью правильного артикула.
Объекты разных модулей могут перекрываться: число рамок нельзя считать остатком.
Система пока не связывает автоматически код с ближайшей коробкой и не распознаёт
операции взятия/возврата. Сохранённый классификатор MobileNet продолжает работать
отдельно; для совместного обзора нужен YOLO Detect либо отключённый модуль товаров.

## Запуск

1. Установите зависимости проекта и `requirements-yolo.txt` через `scripts/setup.ps1`.
   Для существующего окружения добавлены `zxing-cpp==2.3.0`; ONNX исполняется через
   OpenCV DNN на CPU, без ONNX Runtime и без скачивания Python-кода автора.
2. На странице «Обучение» нажмите «Загрузить WarehouseLogistics» либо выберите ранее
   скачанный `weights.onnx` с соседним `weights.json`, созданным нашим загрузчиком.
3. В «Наблюдении» включите «Общий обзор склада» и/или «Читать штрихкоды».
   Активная товарная модель для этих двух режимов не обязательна. Затем включите
   «Распознавать предмет на видео». Смена модулей останавливает текущий процесс;
   включите распознавание снова с новыми настройками.
4. Прочитанные коды появляются в списке. «Выбрать прочитанный код» переносит именно
   выбранную строку в форму товара. Никаких событий или списаний это не создаёт.

Загрузка из CLI:

```powershell
.\.venv\Scripts\python.exe -m pikkabpe.model_sources --data .\data
```

Кадры для декодирования передаются в исходном разрешении в PNG. Детектор общего
обзора получает letterbox 640×640, товарный YOLO — собственный вход 640. Декодер
обрабатывает полный кадр и до 30 найденных областей кода с полями по краям.
Повторное чтение той же области удаляется; одинаковый номер на двух отдельных
этикетках остаётся двумя пространственными результатами. В списке выбора одинаковые
строки объединены. Неизвестные коды не добавляются в каталог автоматически.
GS1 Application Identifiers пока не разбираются: для составного GS1/Data Matrix
нужен отдельный адаптер сопоставления с каталогом; точное совпадение всей строки
работает для простых внутренних кодов. Данные кода не преобразуются в число.

## Предразметка и дообучение

1. Откройте фото или остановите видео, выберите модуль детекции.
2. Нажмите «Предложить рамки моделью». Фиксируется именно этот полный кадр.
3. В таблице выберите предложение. Проверьте товар; для общего класса он намеренно
   не назначается автоматически. При необходимости заново обведите предмет мышью.
4. Нажмите «Принять выбранную рамку для товара». Лишние предложения можно игнорировать,
   ошибочную принятую рамку убрать кнопкой «Убрать последнюю рамку».
5. Добавьте пропущенные экземпляры вручную, затем сохраните разметку полного кадра.
   Только эта операция добавляет данные для обучения. Предсказания сами не сохраняются.
6. Соберите отдельную съёмку каждого товара для проверки. Кадры одной съёмки остаются
   в одной выборке. Точные дубликаты между выборками запрещены; близкие кадры и копии
   с преобразованиями всё равно должен контролировать оператор.
7. В «Исходных весах» выберите обучаемую YOLO `.pt`: готовую базовую модель или прошлый
   товарный checkpoint. Пустое поле использует `yolov8n.pt`, как раньше. ONNX не является
   checkpoint для продолжения обучения и отклоняется.
8. Обучите, проверьте результат и вручную активируйте новую модель. В отчёте сохраняются
   исходные веса, контрольные суммы, съёмки и метрики детектора, включая классы.

В интерфейсе разметки назначаются товары вашего каталога. Дообучение WarehouseLogistics
на общих классах здесь не реализовано: исходного `.pt` нет. Общая модель сохраняется
отдельно. Для будущего объединённого детектора потребуются согласованные классы,
обучаемые веса и размеченные примеры как общих объектов, так и товаров ИНТЭР.
Постоянный независимый тестовый набор для сравнения версий следует собирать отдельно
от используемой для выбора checkpoint проверочной выборки.

- Зафиксированная ревизия: `4b37c4f133cc0b5e13007d272fcfd209700d6615`.
- SHA-256 ONNX: `f695550212d2dd2059928f543f3550690527bc0ed7071dca040e5f12c849e432`.
- 20 классов; YOLOv8n. В ONNX указаны Ultralytics `8.0.134`, дата экспорта
  `2023-10-25T05:50:47.513065`, вход `[1,3,640,640]`, задача `detect`.
- Карточка ссылается на Roboflow Logistics:
  https://universe.roboflow.com/large-benchmark-datasets/logistics-sz9jr
- Полный рецепт исходного обучения и `.pt` в проверенной публикации отсутствуют.
- В `benchmark/synthetic/synthetic_f306cfd697334e638babd02bd4dfc2f6.json` указаны
  10 matched images, 707 GT и 82 predictions; per-class IoU для `barcode` равна 0.
  Общая оценка карточки не подтверждает качество на вашем складе, и эти числа
  нельзя выдавать за mAP или напрямую считать из них recall без описания методики.
- В ONNX указана лицензия AGPL-3.0, в карточке отдельное поле лицензии отсутствует.
  Условия Ultralytics: https://www.ultralytics.com/license
  Загрузчик сохраняет README и происхождение рядом с весами. Веса не включены в Git
  или Windows ZIP. SHA-256 проверяет совпадение с закреплённым артефактом.

## Литература и готовый декодер

- Alsulami, Jhanjhi, *Deep learning framework for barcode localization and decoding
  using simulated UAV imagery*: YOLOv8 локализует коды, OpenCV декодирует области.
  Работа проверена на **симулированных** изображениях; не доказательство точности
  на нашем складе. https://www.nature.com/articles/s41598-025-29720-w
- *Fast, Accurate Barcode Detection in Ultra High-Resolution Images*: отдельно
  рассматривает поиск областей кодов в изображениях высокого разрешения.
  https://arxiv.org/abs/2102.06868
- ZXing-C++: готовый декодер 1D/2D, включая Code128, EAN, QR, Data Matrix.
  https://github.com/zxing-cpp/zxing-cpp

Выбранная реализация следует модульному подходу «локализация → декодирование →
сопоставление с каталогом». Для простых читаемых кодов декодер может найти область
самостоятельно, поэтому поиск по полному кадру не зависит от успеха общей модели.
