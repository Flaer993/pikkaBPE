# PB_MCU01_H503: подключение и первая проверка

Источники: схема V1.0 `D:\12731066989.pdf` и руководство `D:\12731067148.pdf`
(таблица выводов с. 11-16, схема с. 42). На схеме установлен STM32H503CBT6, LQFP48.
Ниже используется нумерация контактов разъёмов H1/H2/H3 со схемы, а не сквозная
нумерация 1-40 из таблицы руководства.

## Интерфейс

USB-C соединён напрямую с PA11/PA12. Отдельного USB-UART моста на схеме нет.
Прошивка реализует USB CDC ACM: Windows видит виртуальный COM-порт, клиент использует
существующие команды P1/CRC16. 115200 - параметр открытия COM, не физическая скорость USB.

| Назначение | Сигнал | Контакт |
|---|---|---|
| Сигнал серво Pan | PA0, TIM2_CH1, AF1 | H1-5 |
| Сигнал серво Tilt | PA1, TIM2_CH2, AF1 | H1-6 |
| Общая земля MCU и питания серво | GND | H1-19 либо H1-20 |
| USB D- | PA11 | USB-C; также H2-13 |
| USB D+ | PA12 | USB-C; также H2-12 |
| Отладка SWCLK | PA14 | H3-2 |
| Отладка SWDIO (на схеме SWIO) | PA13 | H3-3 |
| Отладка GND | GND | H3-1 |
| Отладка Vref | 3,3 В | H3-4 |
| Сброс | NRST | H1-17 |

MCU питается от USB 5 В через стабилизатор 3,3 В платы. Серво питаются от отдельного
стабилизированного источника 6 В, расчётно 5 А на два привода, с общей землёй. Положительный
вывод 6 В не соединять с 5 В/3,3 В платы. Уровень PWM 3,3 В; если конкретный MG995
его не распознаёт, нужен буфер уровня. 6 В на GPIO подавать нельзя.

На предоставленной схеме CC1/CC2 USB-C оставлены без показанных Rd-резисторов:
для первой проверки используйте USB-A -> USB-C кабель с данными. Работа C -> C
по этой схеме не гарантируется. На PA12 есть внешний pull-up 1,5 кОм к 3,3 В;
при проблемах обнаружения после прошивки переподключите USB физически.

## Сборка и поведение

Нужны Python и GNU Arm Embedded GCC. Команды из корня проекта:

```powershell
python scripts/fetch_firmware_deps.py
python scripts/build_firmware.py
```

Можно задать `PIKKABPE_DEPS` и `--gcc` с полным путём к компилятору. На этом ПК:
зависимости в `D:\pikkaBPE-tools\firmware-deps`, компилятор в `D:\pikkaBPE-tools\arm-gcc`.
TinyUSB, ST CMSIS/HAL и CMSIS Core закреплены commit ID и SHA-256 архивов; лицензии
включены в пакет. Выход: `build/pb_h503/pikkaBPE-PB-H503-USB.{bin,hex,elf}`.

Адрес BIN: 0x08000000; HEX уже содержит адреса. Процессор 64 МГц от HSI, USB 48 МГц
от HSI48 с CRS-синхронизацией по USB. Кварц платы 8 МГц в этой конфигурации не используется.
TIM2: PSC=63, ARR=19999, PWM 50 Гц. До первой корректной команды PWM выключен.
Начальная нейтраль 1500 мкс; пределы импульса 1000-2000 мкс требуют проверки хода серво.
После 600 мс без корректной команды движение задания прекращается, последнее положение
продолжает удерживаться. Обратной связи фактического угла MG995 нет.

## Первая стендовая проверка

1. Выключите питание сервоприводов; сверяйте MCU и ревизию со схемой.
2. Подключите ST-Link к SWCLK, SWDIO, GND и Vref. Плату питайте от USB.
3. При необходимости сохраните старую прошивку. В STM32CubeProgrammer запишите HEX
   и выполните Verify. Option Bytes и настройки защиты менять не требуется.
4. Переподключите USB и найдите COM-порт. Лабораторные VID/PID: CAFE:4011; имя
   PB H503 Gimbal CDC. Эти USB ID не являются зарегистрированными идентификаторами
   нашего коммерческого продукта. Серийный номер формируется из UID микроконтроллера.
5. Подключите клиент к COM и проверьте ACK. Измерьте PA0/PA1 осциллографом:
   50 Гц, в нейтрали 1500 мкс.
6. Проверьте один серво без нагрузки, затем второй. Проверьте направление и ход малыми
   шагами. Затем можно переходить к механическому макету на столе.

Статус: BIN/HEX собраны; USB/PWM на физической плате ещё не испытаны. Прошивка на плату
не записывалась. Клиент пока не прошивает MCU: для обновления контроллера нужен ST-Link.
Обновление из клиента потребует отдельного загрузчика и проверки восстановления.
