# pikkāBPE

Домашний прототип операторского учёта склада: Logitech C920, двухосевой подвес MG995,
PB_MCU01_H503A / STM32H503, Windows и локальная SQLite.

## Запуск на этом ПК

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File D:\pikkaBPE\scripts\start.ps1
```

Готовый клиент: `dist/pikkaBPE/pikkaBPE.exe`. Запускающий BAT на рабочем столе использует
`D:\pikkaBPE\data`, включая модели, журнал и БД. При прямом запуске EXE данные по умолчанию
в `%LOCALAPPDATA%\pikkaBPE`; путь можно изменить переменной `PIKKABPE_DATA`.

## Что реализовано

- Видео с USB-камеры или файла, выделение предмета мышью, фиксация снимка.
- Детектор движения и осторожное сопровождение через USB-UART (после подключения/калибровки).
- Справочники товара по штрихкоду, сотрудников и мест; семь стеллажей по умолчанию.
- Взятие, возврат, размещение ожидаемого поступления; отдельное подтверждение оператором.
- SQLite: транзакционный журнал, запрет отрицательных остатков и повторного подтверждения.
- Разметка выделенных предметов, обучение MobileNetV3 Small на NVIDIA, ручная активация.
- Изоляция сессий обучения и проверки; новая модель не меняет остатки самостоятельно.
- CSV подтверждённых событий (внутренний формат, адаптер Sentry WMS ещё не реализован).
- Обновления клиента из приватных GitHub Releases после подтверждения и проверки SHA-256.
- CI: тесты Python и C, запуск UI, сборка Windows ZIP, выпуск при теге `vX.Y.Z`.
- SolidWorks 2024: 12 исходных деталей, сборка, STEP и STL, воспроизводимый генератор.

## Границы версии 0.1.0

Это операторский прототип. Не реализовано автономное распознавание взятия/возврата,
личности сотрудника и конкретного SKU без штрихкода. Motion-подсказка не является складской
операцией. Классификатор обучается на выбранных изображениях предметов, не на событиях.
Пилот из открытых изображений отделён от рабочей БД и не активируется автоматически.

CAD P0 является компоновкой и комплектом посадочных образцов, **не готовой конструкцией
для подвешивания над людьми**. Требуется завершить силовые соединения, удержание осей,
крепления штатных качалок и проверить полный ход с камерой/кабелями. Внешние крепёжные
элементы и серво/камера пока заданы габаритами в документации, не точными CAD-моделями.

Для PB_MCU01_H503A готовы переносимое ядро C и интеграция HAL. Без подтверждённой схемы
выводы не назначены и flash-ready BIN/HEX не выпускается. Обновление MCU из клиента
пока не реализовано; исходники прошивки публикуются в релизе. USB-UART сам по себе
не обеспечивает безопасное обновление прошивки без загрузчика/BOOT0/NRST.

## Файлы

- `cad/native/pikkaBPE_P0.SLDASM` — открывать вместе со всеми SLDPRT в этом каталоге.
- `cad/parameters.json` — исходные размеры и неподтверждённые допуски.
- `cad/step/`, `cad/stl/` — обмен и посадочная печать, миллиметры.
- `docs/manual.md`, `output/pdf/pikkaBPE-manual.pdf` — минимальная документация.
- `firmware/` — C99 ядро, тесты и STM32 HAL adapter.
- `scripts/fetch_seed.py` — загрузка разрешённых открытых изображений с атрибуцией.

## Разработка

Python 3.11. `scripts/setup.ps1` создаёт окружение и ставит зависимости. PyTorch 2.5.1
cu118 / torchvision 0.20.1 выбраны для общей базы RTX 3060 и Pascal P4000; эту версию
нельзя без проверки архитектур заменять последней CUDA-сборкой. На P4000 требуется
проверить драйвер, реальное обучение и время инференса. Локально проверена RTX 3060.

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pikkabpe.train --data D:\pikkaBPE\data --epochs 10
cmake -S firmware -B build/firmware
cmake --build build/firmware
ctest --test-dir build/firmware --output-on-failure
```

Тяжёлые CUDA-библиотеки вынесены в Python-окружение обучения. EXE запускает обучение
и классификацию отдельным процессом; путь к Python указывается на вкладке «Обучение».
На целевом ПК пакет `pikkabpe` должен быть установлен в этом окружении.

## Репозиторий и релизы

Приватный `Flaer993/pikkaBPE`. Требуется GitHub CLI (`gh auth login`) в профиле оператора.
Данные, изображения сотрудников, Telegram-экспорт, модели и пароли не попадают в git.
Тег версии должен совпадать с версиями в `pyproject.toml` и `pikkabpe/__init__.py`.
Подпись Windows пока отсутствует. SHA-256 проверяет целостность, не заменяет Authenticode.
Публичное доверие бесплатного self-signed сертификата не появляется автоматически.

Перед релизом запускайте тесты; `scripts/build.ps1` создаёт ZIP с EXE. Резервная копия
БД делается перед обновлением, прежняя папка приложения сохраняется рядом с новой.
Проверки обновления не скачивают ничего без подтверждения оператора.
